# Properties — First Pass (Tiers 0-10)
Protocol: Ondo Cash (VAULT) + Flux lending (LENDING). Generated by properties-phase-1a.

## Tier 0 — PROFIT (economic / value-conservation)

- **PROFIT-01** [GLOBAL]: Total CASH minted via `claimMint` across all epochs must never exceed `sum(mintRequestsPerEpoch[e][u] * decimalsMultiplier * 1e6 / epochToExchangeRate[e])` for all users `u` and epochs `e`. Impl: ghost `ghost_totalCollateralDeposited` incremented in `requestMint` handler, `ghost_totalCashMinted` incremented in `claimMint` handler; assert `cash.totalSupply() <= ghost_totalCashMinted` and cross-check via exchange rate math. [INFRASTRUCTURE_REQUIRED]

- **PROFIT-02** [GLOBAL]: After `completeRedemptions`, the sum of collateral distributed to all redeemers plus fees must equal `collateralAmountToDist`. Impl: ghost accumulators in `completeRedemptions` handler summing per-redeemer `collateralAmountDue` + fees; assert `sumPayouts + fees == collateralAmountToDist`. [INFRASTRUCTURE_REQUIRED]

- **PROFIT-03** [GLOBAL]: A user cannot receive more collateral in redemption than their proportional share of `totalBurned` for that epoch (pro-rata fairness). Impl: for each redeemer `r` in epoch `e`, assert `collateralAmountDue[r] == (amountToDist * addressToBurnAmt[r]) / quantityBurned` (rounded down). Handler: `completeRedemptions`.

- **PROFIT-04** [GLOBAL]: `claimMint` zeroes `mintRequestsPerEpoch[epochToClaim][user]` before calling `cash.mint` — no double-claim possible. Impl: ghost tracking claim state; assert user cannot `claimMint` same epoch twice successfully. Handler: `claimMint`.

- **PROFIT-05** [GLOBAL]: `requestRedemption` burns CASH atomically and increments `totalBurned`; refund via `_processRefund` re-mints exactly the burned amount — no CASH created or destroyed net. Impl: ghost `ghost_netCashBurned` = burns - refunds; after all ops assert `ghost_netCashBurned >= 0` and equals reduction in totalSupply. [INFRASTRUCTURE_REQUIRED]

- **PROFIT-06** [ORACLE]: Exchange rate used in `claimMint` equals `epochToExchangeRate[epochToClaim]` at time of mint — rate is immutable once set for a given epoch (unless `overrideExchangeRate` is called). Impl: ghost capturing rate at `setMintExchangeRate` time; assert `epochToExchangeRate[e]` never changes unless `overrideExchangeRate` is called. Handler: `setMintExchangeRate`, `overrideExchangeRate`.

## Tier 2 — Solvency / Conservation

- **SOL-01**: `cash.totalSupply()` at any point equals sum of all `claimMint` outputs minus sum of all `requestRedemption` burns plus sum of all `_processRefund` re-mints. Impl: ghost accumulators on `Minted`/`Burned` events; assert `totalSupply == ghostMinted - ghostBurned + ghostRefunded`. [INFRASTRUCTURE_REQUIRED]

- **SOL-02**: `currentMintAmount <= mintLimit` always holds within an epoch. Impl: direct assertion after every `requestMint`. Handler: `requestMint`.

- **SOL-03**: `currentRedeemAmount <= redeemLimit` always holds within an epoch. Impl: direct assertion after every `requestRedemption`. Handler: `requestRedemption`.

- **SOL-04**: After `transitionEpoch` fires, `currentMintAmount == 0` and `currentRedeemAmount == 0`. Impl: assert post-transition state after epoch-advancing calls.

- **SOL-05**: `mintRequestsPerEpoch[e][u] == 0` for all users after `claimMint` completes for that user/epoch. Impl: assert slot is zero post-call.

- **SOL-06**: `redemptionInfoPerEpoch[e].addressToBurnAmt[addr] == 0` for all processed addresses after `completeRedemptions`. Impl: assert zeroed after processing. Handler: `completeRedemptions`.

## Tier 5 — Monotonicity

- **MONO-01**: `currentEpoch` is non-decreasing — it never decreases once set. Impl: ghost `ghost_lastEpoch`; after every call assert `currentEpoch >= ghost_lastEpoch`.

- **MONO-02**: `lastSetMintExchangeRate` only changes via `setMintExchangeRate` (normal path) or `overrideExchangeRate` (admin bypass) — it does not spontaneously change. Impl: assert rate unchanged unless one of those two functions was called.

- **MONO-03** [COVERAGE_PHASE]: cToken `exchangeRateStored()` is non-decreasing over time (interest only accrues positively). Impl: ghost capturing previous exchange rate; assert `exchangeRateStored() >= ghost_prevExchangeRate` after `accrueInterest`. Handler: `accrueInterest`.

- **MONO-04**: `redemptionInfoPerEpoch[e].totalBurned` is non-decreasing within an epoch (only increases via `requestRedemption`, decreases only after `completeRedemptions` via zeroing individual slots, but `totalBurned` itself should be non-decreasing within the epoch). Impl: ghost on `totalBurned` per epoch.

## Tier 6 — Math / Rounding (precision accumulation, share inflation)

- **ROUND-01**: `_getMintAmountForEpoch` rounds down (never over-mints): `cashOwed * epochToExchangeRate[e] <= collateralDeposited * decimalsMultiplier * 1e6`. Impl: assert post-claim. Handler: `claimMint`.

- **ROUND-02**: `_getMintFees` rounds down (fee is never over-collected): `feesInCollateral * BPS_DENOMINATOR <= collateralAmountIn * mintFee`. Impl: assert in `requestMint` handler.

- **ROUND-03**: `_processRedemption` rounds down (user receives at most their pro-rata share): `collateralAmountDue * quantityBurned <= amountToDist * cashAmountReturned`. Impl: assert inside `completeRedemptions` handler.

- **ROUND-04**: Sum of individual `collateralAmountDue` across all redeemers in an epoch cannot exceed `amountToDist` (no over-distribution due to rounding). Impl: ghost accumulator; assert `sumPaid <= amountToDist`. [INFRASTRUCTURE_REQUIRED]

- **ROUND-05** [SHARE_INFLATION]: Exchange rate must never be set to 0 (division by zero / infinite mint). Impl: assert `epochToExchangeRate[e] > 0` after any rate-setting call (enforced by `ZeroExchangeRate` revert in `setMintExchangeRate`, but `overrideExchangeRate` has no such check). Handler: `overrideExchangeRate`.

- **ROUND-06** [SHARE_INFLATION]: If `exchangeRate` is set to 1 (near-zero), `_getMintAmountForEpoch` produces astronomically large `cashOwed`. Property: `epochToExchangeRate[e] >= minSafeRate` where `minSafeRate` is a protocol-defined floor. Impl: flag when rate < 1e3. Handler: `setMintExchangeRate`, `overrideExchangeRate`.

## Tier 7 — Variable Transitions (exact-delta on balances/supply/exchangeRate)

- **DELTA-01**: After `requestMint(collateralAmountIn)`, `mintRequestsPerEpoch[currentEpoch][msg.sender]` increases by exactly `collateralAmountIn - feesInCollateral`. Impl: ghost pre/post delta check. Handler: `requestMint`.

- **DELTA-02**: After `requestRedemption(amount)`, `redemptionInfoPerEpoch[currentEpoch].totalBurned` increases by exactly `amount` and `addressToBurnAmt[msg.sender]` increases by exactly `amount`. Impl: pre/post delta. Handler: `requestRedemption`.

- **DELTA-03**: After `requestRedemption(amount)`, `cash.totalSupply()` decreases by exactly `amount`. Impl: pre/post snapshot. Handler: `requestRedemption`.

- **DELTA-04**: After `claimMint` for user `u` in epoch `e`, `cash.balanceOf(u)` increases by exactly `cashOwed = _getMintAmountForEpoch(collateralDeposited, e)`. Impl: pre/post snapshot. Handler: `claimMint`.

- **DELTA-05**: After `setMintExchangeRate(rate, epoch)` succeeds (no delta violation), `epochToExchangeRate[epoch] == rate` and `lastSetMintExchangeRate == rate`. Impl: post-call assertion. Handler: `setMintExchangeRate`.

- **DELTA-06**: After `setMintExchangeRate` that exceeds delta limit, contract enters paused state. Impl: assert `paused() == true` after such a call. Handler: `setMintExchangeRate`.

- **DELTA-07**: After `transitionEpoch`, `currentEpoch` increases by `floor((block.timestamp - oldStart) / epochDuration)`. Impl: pre/post delta. Handler: `transitionEpoch`.

## Tier 8 — Exchange Rate (CashManager mint/redeem exchangeRate integrity)

- **RATE-01**: `setMintExchangeRate` reverts if `epochToSet >= currentEpoch` — rates can only be set for past epochs. Impl: assert revert when `epochToSet == currentEpoch`. Handler: `setMintExchangeRate`.

- **RATE-02**: `setMintExchangeRate` reverts if rate is already set for that epoch (`epochToExchangeRate[epochToSet] != 0`). Impl: assert double-set reverts. Handler: `setMintExchangeRate`.

- **RATE-03**: When `setMintExchangeRate` sets a rate within delta limit, `|newRate - lastSetMintExchangeRate| <= (lastSetMintExchangeRate * exchangeRateDeltaLimit) / BPS_DENOMINATOR`. Impl: post-call arithmetic check. Handler: `setMintExchangeRate`.

- **RATE-04**: `overrideExchangeRate` bypasses delta limit — MANAGER_ADMIN can set any rate for any past epoch. Property: after `overrideExchangeRate(rate, e, ...)`, `epochToExchangeRate[e] == rate` regardless of delta. Impl: direct assertion. Handler: `overrideExchangeRate`.

- **RATE-05**: `claimMint` reverts if `epochToExchangeRate[epochToClaim] == 0` — rate must be set before claiming. Impl: assert `claimMint` on epoch with unset rate reverts with `ExchangeRateNotSet`. Handler: `claimMint`.

- **RATE-06** [ORACLE]: Manual `OndoPriceOracleV2.setPrice` is unbounded — owner can set any price. Property: price cap (`fTokenToUnderlyingPriceCap`) must be respected when non-zero: `getUnderlyingPrice(f) <= cap[f]`. Impl: assert after `setPrice`. Handler: `setPrice`.

## Tier 9 — Fees (mintFee/redeem fee bounds; fee recipient accounting)

- **FEE-01**: `mintFee < BPS_DENOMINATOR` always — fee cannot be 100% or more (enforced by `setMintFee` revert). Impl: assert `mintFee < 10_000` after any `setMintFee`. Handler: `setMintFee`.

- **FEE-02**: `feesInCollateral = (collateralAmountIn * mintFee) / BPS_DENOMINATOR` and `depositValueAfterFees = collateralAmountIn - feesInCollateral`; both are non-negative and sum to `collateralAmountIn`. Impl: arithmetic assert in `requestMint` handler.

- **FEE-03**: `feesInCollateral + depositValueAfterFees == collateralAmountIn` exactly (no rounding loss at split). Impl: assert equality in handler. Handler: `requestMint`.

- **FEE-04**: Fee recipient receives `feesInCollateral` of collateral on every `requestMint`; asset recipient receives `depositValueAfterFees`. Impl: balance delta check on both recipients. Handler: `requestMint`.

- **FEE-05**: In `completeRedemptions`, `fees` parameter has no on-chain upper bound beyond `collateralAmountToDist`. Property: `fees <= collateralAmountToDist` must hold to prevent underflow on `amountToDist = collateralAmountToDist - fees`. Impl: assert no underflow / revert check. Handler: `completeRedemptions`.

- **FEE-06**: `minimumDepositAmount >= BPS_DENOMINATOR` always (enforced by setter). Impl: assert `minimumDepositAmount >= 10_000` at all times.

## Tier 10 — Doomsday (DOOM: can a user be bricked? can funds be locked?)

- **DOOM-01** [KYC]: If a user loses KYC status after `requestMint` but before `claimMint`, their `mintRequestsPerEpoch` collateral may be permanently locked (they cannot claim; admin must use `setPendingMintBalance` to recover). Property: assert that removal of KYC does not result in unclaimed collateral being permanently stuck without admin intervention path. Impl: document as known admin-recovery path; assert `setPendingMintBalance` can zero out stuck balance. Handler: `setPendingMintBalance`, `removeKYCAddresses`.

- **DOOM-02** [PAUSE]: When paused, `requestMint`, `claimMint`, `requestRedemption` all revert; funds are temporarily inaccessible but not lost. Property: assert these three functions revert when `paused() == true`. Impl: pause → attempt call → assert revert. Handler: `pause`.

- **DOOM-03** [PAUSE]: `completeRedemptions` is NOT guarded by `whenNotPaused` — admin can still service redemptions during pause. Impl: assert `completeRedemptions` does not revert due to pause. Handler: `completeRedemptions`.

- **DOOM-04** [RATE-LIMIT]: If `mintLimit == 0`, every `requestMint` reverts with `MintExceedsRateLimit`. Property: user is bricked from minting until limit is raised. Assert `setMintLimit(0)` followed by `requestMint` always reverts. Handler: `requestMint`.

- **DOOM-05** [RATE-LIMIT]: If `redeemLimit == 0`, every `requestRedemption` reverts. Property: user holdings are temporarily illiquid. Assert revert scenario. Handler: `requestRedemption`.

- **DOOM-06** [ZERO-RATE]: If `overrideExchangeRate` sets `epochToExchangeRate[e] == 0` for a past epoch with pending claims, all `claimMint` calls for that epoch revert with `ExchangeRateNotSet` — collateral deposited is locked without admin re-override. Impl: assert `overrideExchangeRate(0, ...)` results in locked claims. Handler: `overrideExchangeRate`, `claimMint`. [CRITICAL PATH]

- **DOOM-07** [KYC]: Non-KYC'd recipient causes `claimMint(user, epoch)` to revert — a third party cannot trigger a claim for a non-KYC'd user, but a KYC'd user's claim cannot be blocked by others. Impl: assert KYC check on `user` param in `claimMint` reverts for non-KYC'd address.

## Economic / Oracle Properties (from economic-oracles.md)

- **ECO-01** [ORACLE_MANIPULATION]: `epochToExchangeRate[e]` set via `setMintExchangeRate` is bounded by delta limit: deviation from `lastSetMintExchangeRate` must not exceed `exchangeRateDeltaLimit` bps. - **ECO-02** [ORACLE_MANIPULATION]: `overrideExchangeRate` has NO delta limit — MANAGER_ADMIN can set rate to 1 (near-zero), causing `_getMintAmountForEpoch` to produce `cashOwed ≈ collateral * 1e24` (catastrophic inflation). Property: flag when `overrideExchangeRate` sets rate < 1e3 and pending claims exist. Handler: `overrideExchangeRate`. [CRITICAL]

- **ECO-03** [SHARE_INFLATION]: `mintRequestsPerEpoch[e][u]` is zeroed before `cash.mint` in `claimMint` — reentrancy-safe; single-claim enforced. Property: a user cannot claim CASH twice for the same epoch deposit. Handler: `claimMint`.

- **ECO-04** [SHARE_INFLATION]: `_processRefund` re-mints exactly `addressToBurnAmt[refundee]` for each refundee — no inflation possible if `setPendingRedemptionBalance` is not called first. Property: refund amount equals original burn amount for each refundee. Handler: `completeRedemptions`.

- **ECO-05** [FEE_EXTRACTION]: `fees` in `completeRedemptions` is admin-controlled with no on-chain cap relative to `totalBurned`. Property: `fees` should be bounded by a reasonable fraction of `collateralAmountToDist` (no on-chain enforcement — flag when `fees > collateralAmountToDist / 2`). Handler: `completeRedemptions`. [ADMIN_RISK]

- **ECO-06** [FEE_EXTRACTION]: `setMintFee` can set fee to 9999 bps (99.99%) — user deposits nearly all collateral as fee. Property: `mintFee` change should be monotonically logged and bounded; alert when `mintFee > 500` (5%). Handler: `setMintFee`. [ADMIN_RISK]

- **ECO-07** [PRECISION_ACCUMULATION]: For each redeemer in `_processRedemption`, `collateralAmountDue > 0` or function reverts — prevents zero-value redemptions that lock burned CASH. Property: assert either `collateralAmountDue > 0` or revert with `CollateralRedemptionTooSmall`. Handler: `completeRedemptions`.

- **ECO-08** [PRECISION_ACCUMULATION]: Sum of `collateralAmountDue` across all redeemers in `_processRedemption` is at most `amountToDist` (rounding remainder stays with `assetSender`). Property: `sumDue <= amountToDist`. Assert with ghost accumulator. [INFRASTRUCTURE_REQUIRED]

- **ECO-09** [COLLATERAL_RATIO — COVERAGE_PHASE]: `OndoPriceOracleV2.getUnderlyingPrice` uses three paths (MANUAL, CHAINLINK, COMPOUND_V2). For CHAINLINK path, price staleness (`block.timestamp - updatedAt > maxChainlinkOracleTimeDelay`) must revert. Property: assert stale Chainlink feed causes revert or returns 0. Handler: `getUnderlyingPrice`. [REQUIRES_ORACLE_MOCK]

- **ECO-10** [COLLATERAL_RATIO — COVERAGE_PHASE]: Price cap `fTokenToUnderlyingPriceCap[f]` when set must cap `getUnderlyingPrice(f)` output. Property: `getUnderlyingPrice(f) <= cap[f]` when `cap[f] != 0`. Handler: `setPrice`, `setPriceCap`. [COVERAGE_PHASE]

## PHASE 1B

### Tier 11 — State Transitions

Valid lifecycle/epoch transitions; impossible state combinations.

- **T11-01**: `currentEpoch` advances by exactly `floor((block.timestamp - currentEpochStartTimestamp) / epochDuration)` on each `transitionEpoch` call when `epochDifference > 0`; if `epochDifference == 0` all state variables stay unchanged. Impl: pre/post ghost snapshot; assert exact delta. Handler: `transitionEpoch`.

- **T11-02**: `currentEpochStartTimestamp` after `transitionEpoch` equals `block.timestamp - (block.timestamp % epochDuration)` (aligned to epoch grid), never a raw `block.timestamp`. Impl: post-call arithmetic assertion. Handler: `transitionEpoch`.

- **T11-03**: After `setMintExchangeRate` causes a delta violation (rate set AND pause triggered), the contract is simultaneously paused AND the rate is stored — both state changes are atomic. Impl: assert `paused() == true` AND `epochToExchangeRate[e] == rate` in a single post-call check. Handler: `setMintExchangeRate`.

- **T11-04**: `lastSetMintExchangeRate` is NOT updated when `setMintExchangeRate` triggers a pause (delta exceeded path); it retains its pre-call value. Impl: ghost snapshot before call; assert unchanged after delta-violation branch. Handler: `setMintExchangeRate`.

- **T11-05**: `overrideExchangeRate` updates `lastSetMintExchangeRate` only if `_lastSetMintExchangeRate != 0`; when 0 is passed, `lastSetMintExchangeRate` retains its previous value. Impl: two-path assertion. Handler: `overrideExchangeRate`.

- **T11-06**: `setEpochDuration` mid-epoch does not retroactively change `currentEpochStartTimestamp` — the new duration takes effect only at next `transitionEpoch` call. Impl: call `setEpochDuration` then immediately assert `currentEpochStartTimestamp` unchanged. Handler: `setEpochDuration`, `transitionEpoch`.

- **T11-07**: `setPendingRedemptionBalance` correctly maintains the invariant `redemptionInfoPerEpoch[e].totalBurned` by adding/subtracting delta from previous balance — totalBurned never goes negative (underflow protected by Solidity 0.8). Impl: assert `totalBurned >= addressToBurnAmt[user]` at all times after admin setter. Handler: `setPendingRedemptionBalance`.

- **T11-08**: `completeRedemptions` can only service past epochs (`epochToService < currentEpoch`); assert it reverts for current or future epoch. Impl: direct revert assertion. Handler: `completeRedemptions`.

### Tier 12 — Valid State

Impossible/invalid states that should never be reachable.

- **T12-01**: `epochToExchangeRate[e] != 0` is permanent once set — no code path zeros out a previously set rate except `overrideExchangeRate`. Impl: ghost tracking first-set flag per epoch; assert no spontaneous zero. Handlers: `setMintExchangeRate`, `overrideExchangeRate`.

- **T12-02**: `mintRequestsPerEpoch[e][u]` and `redemptionInfoPerEpoch[e].addressToBurnAmt[u]` cannot both be non-zero for the same (user, epoch) simultaneously via normal flows — a user either minted or redeemed in a given epoch. Impl: assert XOR condition after normal ops (note: violable via `setPendingMintBalance`/`setPendingRedemptionBalance` — flag as admin-only exception). Handler: `requestMint`, `requestRedemption`.

- **T12-03**: `redemptionInfoPerEpoch[e].totalBurned >= sum(addressToBurnAmt[u])` for all users `u` in epoch `e` — totalBurned is always at least as large as any individual burn amount. Impl: ghost per-epoch accumulator. [INFRASTRUCTURE_REQUIRED]

- **T12-04**: `kycGroupRoles[group] == bytes32(0)` means DEFAULT_ADMIN_ROLE governs that group (AccessControl fallback) — assigning role `0x00` to a group does not remove the role guard, it maps to the default admin role. - **T12-05**: An address that is sanctioned (per `sanctionsList.isSanctioned`) returns `getKYCStatus == false` regardless of its `kycState[group][addr]` value — sanctions override KYC. Impl: set `kycState = true` then mock sanction; assert `getKYCStatus == false`. Handler: `getKYCStatus`.

Impl: assert `getUnderlyingPrice(f) == rawPrice` when cap is 0; assert `getUnderlyingPrice(f) == cap` when `rawPrice > cap > 0`. Handler: `getUnderlyingPrice`, `setPriceCap`.

- **T12-07**: `minimumRedeemAmount == 0` allows zero-amount `requestRedemption` to reach the `RedeemAmountCannotBeZero` check in `_checkAndUpdateRedeemLimit` — zero redemption always reverts. Impl: assert `requestRedemption(0)` reverts even when `minimumRedeemAmount == 0`. Handler: `requestRedemption`.

### Tier 13 — Peripheral (view consistency, ERC20 metadata, allowances)

### Tier 14 — Dust (rounding dust bounded; tiny amounts don't break accounting)

- **T14-01**: For any `collateralAmountIn >= minimumDepositAmount`, the computed `cashOwed = _getMintAmountForEpoch(collateralAmountIn, e) >= 1` (at least 1 wei CASH), given `epochToExchangeRate[e]` is in a reasonable range (e.g., < 1e24). - **T14-02**: For a user with a very small `addressToBurnAmt` relative to `totalBurned`, `collateralAmountDue` may round to 0 and trigger `CollateralRedemptionTooSmall` revert — no silent dust absorption. - **T14-03**: `_getMintFees` with `mintFee = 1` (1 bps) and `collateralAmountIn = minimumDepositAmount (10_000)` returns exactly 1 — rounding is strictly down, no zero-fee leakage. Impl: assert `_getMintFees(10_000) == 1` when `mintFee == 1`. Handler: `requestMint`.

### Free-Form Discovery (line-by-line review of top-priority contracts)

- **FF-01** `setMintExchangeRate` for epoch with zero requests: If `setMintExchangeRate` is called for a past epoch in which no user deposited (`mintRequestsPerEpoch[e][u] == 0` for all `u`), the rate is stored but `claimMint` for that epoch will always revert with `NoCashToClaim`. The rate occupies a storage slot permanently with no functional use. Property: assert this is non-reverting but results in a permanently unused rate slot. No invariant is broken, but it is wasted admin gas and storage — flag in fuzzer via ghost tracking epochs-with-rate-but-no-deposits. Handler: `setMintExchangeRate`.

- **FF-02** `completeRedemptions` called twice for same epoch subset: An address in `redeemers` whose `addressToBurnAmt` was already zeroed by a prior `completeRedemptions` call will have `cashAmountReturned = 0`, resulting in `collateralAmountDue = 0` and a `CollateralRedemptionTooSmall` revert — it is impossible to silently double-pay the same redeemer. Property: assert second `completeRedemptions` including an already-serviced address reverts. Handler: `completeRedemptions`. [CRITICAL — double-service protection]

- **FF-03** `transitionEpoch` griefing: `transitionEpoch` is `public` with no access control — any caller can trigger it. However, since all state-changing ops also call it via `updateEpoch`, there is no griefing vector beyond wasted gas. Property: assert `transitionEpoch()` called externally by a non-admin cannot brick any user operation in the same block. Handler: `transitionEpoch`.

- **FF-04** `multiexcall` arbitrary-call surface: `multiexcall` is only callable when paused and by MANAGER_ADMIN. The call is made with `msg.sender == address(CashManager)`, so it can invoke `cash.mint`, `collateral.transfer`, or any other contract that grants CashManager a role. Property: assert that `multiexcall` cannot be called when unpaused; assert reentrancy via `nonReentrant` prevents any reentrant `requestMint`/`claimMint` loop. Impl: assert `multiexcall` reverts when not paused; note `nonReentrant` guard is present. Handler: `multiexcall`.

- **FF-05** KYC removal mid-flow stranding redemptions in `completeRedemptions`: If a redeemer loses KYC between `requestRedemption` and `completeRedemptions`, `_checkAddressesKYC` reverts for the entire batch — all redeemers in the array are blocked until the de-KYC'd address is either re-approved or removed from the array (via `setPendingRedemptionBalance(addr, epoch, 0)` then admin re-calls without that address). Property: assert that a single non-KYC'd address in `redeemers` causes full batch revert. Impl: revoke KYC mid-flow; assert `completeRedemptions` reverts with `KYCCheckFailed`. Handler: `completeRedemptions`. [CRITICAL — admin operational risk]

- **FF-06** `assetSender == address(0)` DoS: `setAssetSender` accepts `address(0)` (no zero-address check in the setter, unlike constructor). If set to zero, `collateral.safeTransferFrom(address(0), ...)` in `completeRedemptions` and `_processRedemption` will revert — all redemptions/refunds are bricked. Property: assert `setAssetSender(address(0))` succeeds but then `completeRedemptions` reverts. Handler: `setAssetSender`, `completeRedemptions`. [MISSING VALIDATION]

- **FF-07** `epochDuration == 0` division-by-zero in `transitionEpoch`: If `setEpochDuration(0)` is called, the next `transitionEpoch` call divides by zero in `(block.timestamp - currentEpochStartTimestamp) / epochDuration`. Property: assert `setEpochDuration(0)` followed by any `updateEpoch`-decorated function reverts with division-by-zero. Handler: `setEpochDuration`, `transitionEpoch`. [MISSING VALIDATION — CRITICAL]
